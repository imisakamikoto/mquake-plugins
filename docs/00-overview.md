# 00 · 架构总览

## 1. `.mqe` 是什么

`.mqe`（**Mquake Extension**）是一个标准 ZIP 文件，扩展名固定为 `.mqe`。
包内是纯文本 + 数据 + 可选资源/脚本，**根目录下必须有 `plugin.json`**：

```
com.example.myplugin.mqe   (ZIP)
├── plugin.json            清单：能力 / 权限 / 通道 / 配置表单（必需）
├── data.json              静态数据（file 通道）
├── features.geojson       GeoJSON 叠加层
├── main.py                子进程脚本（process 通道，可选）
├── assets/                音效、图片等资源（可选）
└── README.md              插件说明（可选）
```

宿主把它解到 `data/plugins/<id>/`，之后所有相对路径都相对于该目录。
**开发时**也可以直接把解开的目录放进 `data/plugins/`，改文件后点「立即刷新」，
不用反复打包。

## 2. 为什么不能「写 Dart 插件」

主程序用 Flutter 发布版 AOT 编译：

- Dart 在 AOT 下没有 `eval`、没有动态库加载 Dart 源码的能力；
- iOS / Android 明确禁止运行时下载并执行代码；
- 主程序还需要签名、审计与确定性构建。

因此插件系统采用**声明式清单 + 数据协议 + 内置能力引擎**：
宿主提供所有渲染与调度能力，插件只描述「我要什么能力、数据从哪来、数据长什么样」。
如果确实需要写逻辑，用 `process` 通道跑独立进程，或 `http` / `websocket` 连到自己的服务 —
**语言不限**（Python / Node / Go / Rust / C# / shell 都行）。

## 3. 分层与数据流

```
┌──────────────────────── 你的插件 ────────────────────────┐
│  data.json / HTTP 服务 / WS 服务 / 独立进程 (stdout JSONL) │
└───────────────────────────┬──────────────────────────────┘
                            │ 一条 JSON 报文
                            ▼
┌───────────────────── 宿主：插件运行时 ───────────────────┐
│  PluginPackage  解包 / Zip Slip 防护 / 清单校验            │
│  PluginRuntime  发现 / 启停 / 配置 / 持久化 / 状态          │
│  _Worker        每个插件独立：file / http / ws / process    │
│  PluginMessage  报文解析、字段映射、snapshot/patch 合并      │
│  PluginSnapshot 按能力 + 权限过滤后的不可变聚合快照          │
└───────────────────────────┬──────────────────────────────┘
                            ▼
┌───────────────────── 宿主：展示层 ────────────────────────┐
│  事件列表（插件段）  地图叠加层  设置→插件页的卡片/指标预览  │
│  数据源状态面板（每个插件一行健康度）                       │
└───────────────────────────────────────────────────────────┘

        ✗ 不进入：提示音 / 全屏弹窗 / TTS / 系统通知 / 震源推算
```

关键点：

- **每个插件一个 worker**，独立 `http.Client`、独立定时器、独立 try/catch。
  一个插件超时、崩溃、输出垃圾数据，不影响官方数据源和其它插件。
- **能力过滤发生在两个地方**：报文合并进 worker 时按 `capabilities` 丢弃未声明的分区；
  生成 `PluginSnapshot` 时再按权限过滤（`overlay` / `sound`）。
- **所有 id 加命名空间**：`<pluginId>:<原始id>`，插件之间不会互相覆盖。
- **状态持久化**：启用状态、用户配置、拉取/错误计数写在
  `data/plugins/plugins_state.json`，重启后保留。

## 4. 生命周期

| 阶段 | 发生什么 |
| --- | --- |
| 发现 | 扫描 `data/plugins/`：目录（含 `plugin.json`）与 `.mqe` 文件。`.mqe` 会在校验后解包到同名目录。 |
| 校验 | 清单 schema、id、能力、权限、通道、白名单、路径安全。错误一次列全，不合格不落盘。 |
| 启用 | 创建 worker，按通道启动（立即拉一次，然后按间隔轮询 / 建立长连接 / 拉起子进程）。默认**关闭**，需用户在设置页打开。 |
| 运行 | 每次报文解析 → 按能力过滤 → snapshot/patch 合并 → 重建只读快照 → 通知 UI。 |
| 错误 | 记录 `lastError`、错误计数、日志；插件继续按间隔重试，不会退出。WS 断线 5 秒后重连。 |
| 停用 | 停 worker、取消定时器/订阅、关连接、杀子进程，并从聚合快照移除数据。 |
| 卸载 | 停用 + 删除目录与 `.mqe` 包 + 清状态。 |

## 5. 告警隔离（最重要的设计约束）

紧急地震速报（EEW）的警报音、全屏弹窗、TTS 与系统通知是一条严肃的链路。
插件**默认完全隔离在它之外**：

1. 插件事件转成 `EarthquakeEvent` 时 `isEew = false`；
2. 只追加到事件列表 `events`，**不进** `activeEew`；
3. `_playEventSounds(active)` 只看 `activeEew`，插件数据永远到不了；
4. 测站只用于地图绘制，不喂给 `AudioService.onStations`，也不喂给本地震源推算 `HypoService.ingest`；
5. `source` 统一标记 `插件:<插件名>`，界面可一眼区分；
6. 即使清单写 `permissions.alerts: true`，宿主构造 `PluginRuntime` 时
   `allowPluginAlerts` 默认 `false`，仍会拒绝。

**结论：插件可以补充信息，但不能伪造官方预警。** 这是刻意的安全边界，不是限制遗漏。

## 6. 与其它扩展点的关系

主程序还有两个既有约定，插件不与之冲突：

- `data/sound/*.wav` 运行时音效覆盖机制 — `sounds` 能力走的是插件自己的映射，
  不会改写用户 `data/sound/` 里的文件。
- `StationReplayStore` / 回放包 `.mqp.gz` — 插件测站不写入历史回放，避免污染回放存档。

## 7. 版本与兼容

- 清单 `schema` 当前为 **1**。宿主遇到更高的 schema 会**拒绝加载**并给出明确错误，
  不会猜测字段含义。
- 字段解析故意宽容：缺字段用默认值、数字可以是字符串、多字段忽略、坏条目只跳过该条。
  这样插件作者不必为了一个字段格式化整份数据。
- 新增能力只会**增加**枚举值，不会重定义已有字段。
